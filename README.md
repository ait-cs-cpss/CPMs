# CPMs – Context-Based Proposition Maps

CPMs bridges automata learning and model checking for the security verification of black-box systems.
It takes a learned Mealy machine (Graphviz DOT format) and a **context-based proposition map (CPM)** that
describes, for a given protocol, which input/output combinations make security-relevant propositions
(e.g., *authenticated*, *protected*, *access granted*) true or false. From these, it generates

- an **annotated Mealy machine (AMM)**, i.e., a learned model whose states carry propositions, and
- a **Rebeca model and property file** that can be checked with the Rebeca Model Checker (RMC),
  e.g., via the [Afra](https://rebeca-lang.org/) IDE.

Because the security properties are formulated over propositions rather than protocol messages, the same
generic properties (authentication, confidentiality, privilege levels, key validity) can be reused for any
system speaking a protocol for which a CPM exists.

The method and its formal foundations are described in the accompanying article (see [Publication](#publication)).

## Workflow

```
Learned Mealy machine (.dot) ──┐
                               ├─► Annotation ──► AMM ──► Rebeca model (.rebeca) ──┐
CPM ───────────────────────────┤                                                   ├─► RMC ──► result
Generic security properties ───┴─► Property writing ──► Rebeca property file ──────┘
```

Models can be learned with any automata learning framework that exports Mealy machines in DOT format
(e.g., [LearnLib](https://learnlib.de/) or [AALpy](https://github.com/DES-Lab/AALpy)).
CPMs itself has no dependencies beyond the Java standard library.

### CPM format

<!-- TODO: describe the concrete file format. Conceptually, a CPM consists of three tables: -->

| Section | Meaning |
|---|---|
| Gains | Input/output combinations after which the target state gains a proposition |
| Losses | Input/output combinations after which the target state loses a proposition |
| Implicit state propositions | Propositions that hold only directly after a transition (e.g., a successful read) |

Propositions are inherited by successor states unless a loss condition applies.
